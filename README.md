# ConnectCall

A feature-rich, real-time Audio and Video Calling application built with Flutter. This project was developed as a technical showcase for establishing secure, peer-to-peer communication using industry-standard SDKs.

## Project Description
ConnectCall is a Flutter-based mobile application that allows users to authenticate, add contacts, and initiate high-quality audio and video calls. It uses a modern tech stack to ensure reliable background call notifications (CallKit) and seamless real-time communication across Android and iOS platforms.

## Features
- **Phone Authentication:** Secure login using Firebase Authentication.
- **Contact Management:** Add friends via phone number and view online/offline status.
- **Real-Time Video & Audio Calls:** High-quality, low-latency WebRTC calls.
- **CallKit Integration:** Receive calls natively on the lock screen / background.
- **Call Controls:** Mute microphone, disable camera, switch cameras, and toggle speakerphone.
- **Call States & Error Handling:** Graceful handling of Calling, Connected, Missed, Rejected, and Ended states. Also handles network drops and permission denials without crashing.
- **Call History:** View logs of incoming, outgoing, and missed calls.

## Tech Stack Overview

### Flutter Version
- Flutter 3.10.8 (or higher)
- Dart SDK 3.x

### Backend Used
- **Firebase Firestore:** For real-time database sync (user status, call signaling, and history).
- **Firebase Authentication:** For secure Phone OTP login.
- **Firebase Cloud Messaging (FCM):** For triggering background push notifications.

### Calling SDK Used
- **Agora RTC Engine (`agora_rtc_engine`)**: Used for establishing the WebRTC communication channels, routing audio/video, and managing network quality.

### Packages Used
- `flutter_riverpod` (State Management)
- `firebase_core`, `firebase_auth`, `cloud_firestore` (Backend & Auth)
- `agora_rtc_engine` (Audio/Video SDK)
- `flutter_callkit_incoming` (Native incoming call UI)
- `firebase_messaging` (Push notifications)
- `permission_handler` (Camera/Mic access)
- `connectivity_plus` (Network status)
- `device_info_plus` (Dynamic rendering strategies)

## Architecture
This project follows a **Feature-first / Layered Architecture**:
- `lib/models/`: Data models (e.g., `UserModel`).
- `lib/services/`: Core business logic separated from the UI (`CallService`, `AuthService`, `UserService`).
- `lib/screens/`: The presentation layer, divided by feature (`auth`, `home`, `call`).
- `lib/core/`: Application-wide configurations like Themes.

Services communicate with the UI via **Riverpod** providers. This ensures the UI remains dumb and only reacts to state changes broadcasted by the services.

## Setup Instructions
1. Clone the repository:
   ```bash
   git clone <repository_url>
   ```
2. Install dependencies:
   ```bash
   flutter pub get
   ```
3. Ensure you have an Android Emulator or Physical Device connected.
4. Run the app:
   ```bash
   flutter run
   ```

## Environment Variables / Configuration
- **Firebase:** You must add your own `google-services.json` (Android) and `GoogleService-Info.plist` (iOS) files to connect to your Firebase project.
- **Agora App ID:** The Agora App ID and Temp Token are currently hardcoded in `video_call_screen.dart` and `audio_call_screen.dart` for testing purposes. In a production environment, these should be moved to `.env` files and tokens should be generated by a secure backend server.

## Known Limitations
- **Hardcoded Tokens:** Currently using an Agora Temp Token. A production app requires a token server to generate unique tokens per session.
- **iOS Backgrounding:** While Android is fully supported, iOS push certificates (APNs) must be configured in your Apple Developer account for CallKit to wake the app on iPhones.
